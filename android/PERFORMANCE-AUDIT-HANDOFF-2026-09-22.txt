CONFIRMED OPPORTUNITY 1 - UNNECESSARY AUTOMATIC SMAA READBACK AUDITS

Location: generated port/fast3d/gfx_opengl.cpp, gfx_opengl_smaa_audit() and
gfx_opengl_grade_frame(); generated from the SMAA patch stack.

The baseline automatically performs an audit 2 and 120 frames after an AA
selection or target-size change. It reads FOUR full-resolution RGBA buffers
back to CPU, allocates THREE full-resolution byte vectors, and scans the pixels
for edge, blend-weight and output-difference statistics. This still runs with
gfx_smaa_debug == 0 although the diagnostic rows were removed from the menu.

This is a defensible source of intermittent extra work/stalls, NOT proof that
it caused the user's sustained ~50 FPS menu behavior. At 1920x1080 the source
requests 33,177,600 bytes across four readbacks and 24,883,200 bytes of vector
payload per audit. Those are calculated payload sizes, not measured device
memory usage or measured bus traffic.

Draft change: make automatic audit opt-in using PD_POSTFX_AUDIT (default 0) or
an explicitly selected diagnostic view. Retain the diagnostic code, and define
PD_POSTFX_AUDIT=1 in the existing GLES diagnostic test harness.

Measured: baseline scheduled audit frame performed 4 production glReadPixels
calls; the production-config draft performed 0. Output pixels were identical.
No AA mode or image-processing pass was removed. This changes diagnostic
collection, not AA quality. The normal diagnostic test still exercised audits.

CONFIRMED OPPORTUNITY 2 - REPEATED POST FX UNIFORM LOCATION LOOKUPS

Location: generated gfx_opengl_grade_frame().
Baseline performed one glGetUniformLocation per FXAA/Post FX frame and twelve
per normal full SMAA frame. Programs already remain linked between frames.

Draft change: store these locations at successful program initialization,
separately for both SMAA quality variants. Reinitialize every location when
programs are recreated; use -1 for unavailable SMAA programs so the existing
Lite fallback remains valid. Do not cache solely by GLuint across lifetimes.

Measured: 1 -> 0 lookups for ordinary FXAA frames; 12 -> 0 for SMAA frames.
Steady-state compile/link counts were already zero and remain zero. This pass
does not claim to have fixed per-frame compilation that was not happening.

CONFIRMED OPPORTUNITY 3 - OVERBROAD POST FX STATE GUARD

Location: generated struct PostFxState and grade_frame().
The original guard queries and changes pixel-unpack/PBO state on every frame,
even though only initialization and resize upload/allocate textures. It also
queries the default read-buffer selector twice when the caller already uses
the default read framebuffer, resets already-zero sampler bindings, disables
already-disabled capabilities, and repeats four disables later in the pass.

Draft change:
- Save/reset/restore unpack state only when initialization or size change can
  allocate/upload textures. First-use and resize still use the full guard.
- Reuse the read selector already queried when read_fbo == 0.
- Change capability and sampler states only when the saved value requires it.
- Remove the four disables already performed by the guard.
- Retain queries for externally mutable caller state rather than inventing an
  incomplete global GL cache. All touched state must still be restored.
